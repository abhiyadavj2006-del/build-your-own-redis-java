Build Your Own Redis — in Java

A minimal, real Redis clone: a TCP server on port 6379 that speaks the RESP protocol. Pure Java 21 standard library — no dependencies, no Docker.

What it does

It is a working in-memory key–value store you can talk to with redis-cli or any RESP client, exactly like real Redis. It handles many clients at once (one virtual thread per connection) and supports key expiry.

CommandWhat it does
PING [message]Replies +PONG (or echoes the message)
ECHO messageEchoes the message back
SET key value [EX seconds | PX ms]Stores a value, optionally with an expiry
GET keyReturns the value, or nil if missing / expired
DEL key [key …]Deletes keys, replies with how many were removed
EXISTS key [key …]Counts how many of the keys exist
TTL keySeconds until expiry (-1 = no expiry, -2 = missing)

Example session

Run the server, then talk to it with redis-cli:

$ redis-cli -p 6379 PING
PONG
$ redis-cli -p 6379 ECHO "hello world"
"hello world"
$ redis-cli -p 6379 SET name luna
OK
$ redis-cli -p 6379 GET name
"luna"
$ redis-cli -p 6379 SET temp v PX 200
OK
$ redis-cli -p 6379 GET temp   # after 200 ms
(nil)

Under the hood, redis-cli sends RESP — arrays of bulk strings. A PING on the wire is *1\r\n$4\r\nPING\r\n and the server answers +PONG\r\n. You can try it with plain nc:

$ printf '*1\r\n$4\r\nPING\r\n' | nc localhost 6379
+PONG

How to run it

# Needs Java 21+ — no build step, no dependencies
$ java src/RedisServer.java
redis-clone listening on port 6379 (RESP, Java 21)

# Or compile first:
$ javac -d out src/RedisServer.java
$ java -cp out RedisServer

# Run the test suite (30 checks: PING, ECHO, SET/GET,
# expiry, errors, concurrent clients):
$ python3 tests/test_redis.py
Note: this page is a static demo — the Redis server itself can't run in a browser. It runs on your machine (or any machine with Java 21) and listens on TCP port 6379. See the README for deploy options.

What it doesn't do (yet)

  • Data is in memory only — everything is lost when the server stops (no persistence / RDB / AOF).
  • No lists, sets, hashes or sorted sets — strings only.
  • No authentication, no replication, no clustering, no pub/sub.
  • Single-process, single-node.
